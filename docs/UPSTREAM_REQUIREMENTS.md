# Targeted public SDK requirements

Baseline: OpenClaw 2026.9.3. These are integration dependencies for the accepted scope, not submitted or merged upstream changes. Loops does not import private implementations inspected for diagnosis.

| ID | Released gap | Proposed public addition | Acceptance |
|---|---|---|---|
| SDK01 | `LlmCompleteCommonParams` omits topP, penalties, seed, stops and provider extensions. Temperature/maxTokens are advisory. | Typed parameter-capability discovery and per-call generation overrides, with support and normalization metadata from the runtime owner. | Actual transport tests for inheritance, zero, invalid/unsupported/advisory values, Ollama greedy normalization and native Codex behavior; no global config writes. |
| SDK02 | Commands have bound completion; tool/session-action contexts lack an equivalent account/runtime-bound execution handle. | Invocation-bound model, reasoning, runtime and credential owner, with explicit authorized overrides. | Two accounts for one provider remain distinct across UI/tools/commands/waits/retries; no owner-credential fallback. |
| SDK03 | Session-action clients expose connection ID and broad scopes, not stable principal and target-session authorization. Session IDs change on reset. | Public authorization for read/control/authoring and history generations, with principal identity and delegated-agent restrictions. | Owner/member/read-only/other-session/team-role/reset/reassignment matrix; independent-customer isolation. |
| SDK04 | Delayed delivery needs legitimately retained requester-bound authority; several wake/delivery helpers are trusted-plugin-only. | Durable destination-bound receipt registration and later delivery redemption with dedupe and revocation. | Completion after the initiating request ends and after restart; no duplicate or cross-session delivery. |
| SDK05 | Native plans/goals, compaction, core-tool execution and subagent wake semantics vary across external-plugin surfaces. | Narrow runtime-owned operations preserving permission, cancellation, budgets and native task ownership. | Actual native plans/goals/subagents/tools/compaction with failure/restart tests; no prompts pretending to perform native operations. |

Define adapter contracts and tests in Loops, contribute narrow corresponding SDK changes upstream, then raise the minimum host version only when a released SDK supplies the necessary contract. Do not label a local fork supported OpenClaw or use operator credentials to bypass a trusted-plugin restriction.

## Local SDK01 candidate

Local OpenClaw commit `381afd2238dd694519be89823f2903eb736b1123`, based on `1e802bc6982e035fe74bda7700a129d567f11554`, adds the seven isolated-completion controls `maxTokens`, `temperature`, `topP`, `frequencyPenalty`, `presencePenalty`, `seed` and `stop`. It validates finite numbers, copies stop sequences at admission, preserves omission and explicit zero, and carries the values through the host-prepared OpenAI Chat Completions simple route. Its immutable descriptors describe acceptance at the SDK boundary and remain advisory. They do not yet discover support for each selected runtime owner or model.

Request-capture tests cover actual provider entry-point shaping without sending a network request, including zero, omission and unchanged direct/managed routes. Focused provider tests, core/extension type lanes, canonical declarations, exports and surface checks pass. Fresh independent review found no remaining issue within that declared scope. The canonical API comparison of those exact revisions reports no added or removed subpaths and digest `8445743b59c33f97b49bbf2f26542b0256d8ea403f8cf49a3d412b0136b60722`; this is an inspected local comparison, not upstream owner acceptance or publication. Private evidence is under `evidence/upstream-sdk01/`.

The candidate is neither installed in the development Gateways nor released upstream. Other provider mappings remain narrower; for example the Responses simple route replaces `maxTokens: 0` with the model limit. Actual provider acceptance, Ollama normalization, owner-specific discovery and a released minimum host version remain SDK01 work.

Native Codex was checked against its exact pinned source, `rust-v0.153.4` at `3d2ee51ca2d5db578f328aa75e20aa22c0197c9a`. Its `TurnStartParams` and actual Responses request constructor do not expose per-turn sampling controls. Reasoning effort is supported, but the inspected OpenClaw native isolated route drops the supplied level and the shared bounded helper forces `low`.

Local follow-up commit `7fd7ed268058ef43e1ebc666da947582daf48afa` repairs that native reasoning path. It forwards the requested level, uses already-resolved model capabilities and the existing mapper, inherits native defaults for omission/adaptive, and rejects unsupported explicit off before starting a thread. Specialized media/search/finalization workers request their existing low policy explicitly. The 43 bounded/isolated tests, 54 impacted-worker tests, extension production/test type checks, formatting and focused lint pass; fresh independent review found no blocking issue. This is still an uninstalled, unpublished upstream candidate. Live-default model selection, broader native authority/cancellation cases and actual native transport acceptance remain integration evidence gaps.
