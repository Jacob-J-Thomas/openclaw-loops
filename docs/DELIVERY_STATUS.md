# Delivery status

Loops remains an external OpenClaw plugin with the existing `loops-poc` runtime identity and migration path. The nine-node 1.0 palette is implemented. **Version 1.0.0 is prepared as an unpublished release candidate; it is not a stable publication.** It awaits final candidate-specific checks, acceptance, ClawHub publication and a fresh registry installation/migration check. Practical accessibility remains required, and native screen-reader observability under [Bolt #185](https://github.com/Jacob-J-Thomas/openclaw-loops/issues/185) is incomplete.

The active scope is the standalone plugin's requirements R01–R25 and packages P0–P6 in [the delivery plan](DELIVERY_PLAN.md). Advanced expansion, outgoing-notification AbortSignal/delayed durable notifications, automatic conversation model/account inheritance parity, independent shared-team principals and new cross-session recovery are post-1.0. No OpenClaw issues, PRs, comments or patches are part of the goal; host patches, private provider clients and personal profiles are excluded from this repository and package. GitHub native issue edges and owner acceptance receipts are authoritative; the [roadmap index](ROADMAP_ISSUES.json) preserves the initial 116 issues.

## Evidence boundaries

Real provider and native browser evidence is separate from deterministic adapters. Sampling values described as transmitted were observed at the public host boundary; that is not proof of provider enforcement. A settled local promise or worker is not proof that a remote provider stopped. Gateway connection scopes are not independent human-principal identities. Separate Gateways provide customer state boundaries; one shared library is not tenant isolation.

The original POC archive and historical receipts remain private or in [verification history](VERIFICATION.md). Raw profiles, transcripts, logs and customer fixtures are not published. No model allowlist, provider implementation, bypass of host policy or hidden restriction is introduced to disguise an unavailable contract. Stable 1.0 remains gated on the revised in-scope requirements, including practical accessibility and actual registry qualification. Missing optional host enhancements do not block that release.
