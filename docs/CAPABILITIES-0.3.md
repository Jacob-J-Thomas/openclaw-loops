# Capabilities and boundaries

This external feature plugin targets **OpenClaw 2026.9.3**, an experimental API contract. The exact installed export catalog is recorded in `evidence/sdk-exports.json`. Runtime imports use only public `openclaw/plugin-sdk/*` exports. The package is installed through `plugins install npm-pack:…`; it remains an external plugin. It does not import host internals, impersonate a bundled plugin, or invoke the privileged HTTP tools endpoint.

| Surface | Implemented path |
|---|---|
| Native UI | `defineControlUiPlugin`, registered native page/navigation, `host.sessions`, `createFeatureClient` session actions |
| Shared API | `defineFeatureContract` / `defineFeaturePlugin`; seventeen operations, thirteen tools |
| User command | `api.registerCommand` for `/loops`; same Engine service |
| Inference | `api.runtime.llm.complete`, `isolated-agent-runtime`, zero tools, 512 output tokens, thinking off, signal and execution deadline |
| Read-only action | `api.runtime.modelConfig.resolveDefaultModelForAgent` returns the current caller agent's configured provider/model |
| Owner checks | Trusted command/tool/session-action contexts plus current `api.runtime.agent.session.getSessionEntry` |
| Persistence | One atomic plugin-owned file beneath `api.runtime.state.resolveStateDir()`; never host database writes |

**Host-backed nodes:** Inference and the accurately named **Read configured agent model** Action. Web search is visibly unavailable in this development profile. There is no generic action dispatcher, arbitrary tool name, shell, credential read, configuration write, or external send. Enabling through an authorized agent tool or operator UI grants only the graph's declared supported capabilities; current grants and host/session availability are checked before resume and each node/action. Host model/auth preparation and completion policy remain OpenClaw's responsibility.

**Plugin logic:** Input, Condition, structured Repeat, manual Wait, Human review, Return and Fail. Human review is explicitly a plugin operation, not a claim to use a host approval token. It requires an authenticated `operator.admin` session action and records a decision against the stored proposal. Generic Continue and all tools cannot approve it. Native UI is trusted host-origin code; Shadow DOM isolates styles, not security authority.

The POC intentionally supports the **main agent and authenticated local operator**. The tool factory's agent/session/conversation and optional active model come from the host. Models/users cannot supply those identity fields. Inspection, cancellation, and continuation require the same agent/session/conversation identity. Changing/resetting a conversation prevents access under the old identity. This is not a multi-user SaaS authorization design.

**Agent lifecycle control (0.3.0):** The user's follow-up explicitly replaces the original handoff's human-only activation rule. Authorized main-agent tools can read, create, edit, enable, disable, revoke, delete and invoke loops. Creation enables a validated loop by default; `enabled:false` creates a draft with no grants. Editing preserves activation by default, or accepts an explicit enabled/draft choice. Enabled saves validate and check host capabilities before committing definition or grants, so a rejected publish is atomic. The UI supports Save draft, Save & enable, and direct enable/disable without separate capability checkboxes. Operator write/admin scopes authorize loop management; read-only operators cannot mutate. Actual Human review node decisions remain authenticated admin UI operations.

Definitions are shared across the main agent's chats; run inputs/results remain conversation-scoped. Tool guidance directs mutations only on user request, including enabling a requested loop as part of invoking it unless the user asks to keep it disabled. This is guidance, not a separate natural-language approval token. Create assigns identity/revision, edits detect stale revisions, and activation uses the current revision. Delete refuses active/parked runs, including cancelled calls still settling, and retains terminal run evidence. Recreating a slug assigns a new identity.

Run records retain immutable pinned definitions. Saving an enabled revision does not change existing runs. Saving a draft or disabling blocks new starts and retains existing grants so parked runs remain controllable. **Revoke all grants** also prevents further host actions in existing runs. Enabling grants only the current definition's capabilities; existing runs recheck the current grant and host policy at each action. A pinned definition is never a permanent permission grant. Retrying the same retained request returns its existing record without dispatching again.

OpenClaw registers tools in a separate registry scope from its started Gateway services. A plugin-namespaced process registry resolves one executor per state directory across those registrations; only service startup creates it. This shares plugin state without accessing host internals or opening a privileged transport.

There is one sequential frontier. Repeat has an Inference/Condition body, at most five attempts, with early exit on true. Exhaustion is visible and proceeds to the explicit next node; it does not mean success. Limits: 32 top-level nodes, 64 edges, 40 total node executions including body nodes, 180 seconds active execution, 8 KB per output, 48 KB aggregate trace output, 16 KB input, 64 KB definition, 20 saved loops, 50 retained runs and two active runs. Defaults are 24 executions, 120 active seconds and 4 KB per output. Ollama separately serializes inference to fit memory. Wait/review parked time does not consume the active timeout.

Wait and Human review survive normal Gateway restart. The executor persists a cursor and outputs rather than a JavaScript continuation. Restart during an in-flight call produces `interrupted` with unknown-outcome evidence; it never replays that call. Cancellation stops later dispatch and reports uncertainty for a call already in flight. There is no exactly-once external-effects claim, arbitrary crash recovery, timer wakeup, background polling model task, or automatic later chat delivery. Chat tools return compact receipts with the actual short result, revision, model and state; oversized results are explicitly marked as previews, while the owner-scoped graphical inspector retains the full record. After ten seconds, still-running work returns a truthful handle while the Gateway service keeps ownership of the execution. Inspect its eventual result with status or the UI; a repeated admission does not launch another execution. Local private state retains bounded supplied inputs/results; exported definitions and packaged evidence omit private conversations and credentials.

**Alternative facilities assessed:** Task Flow could supply durable run records, but would still need plugin wake/recovery logic and an independently proven owner-binding adapter. The small authoritative JSON store avoids competing stores and is sufficient for this POC. Lobster is optional; its documented embedded `llm-task` / nested `openclaw.invoke` limitation makes it unnecessary for this direct completion path. Neither facility is silently assumed available.
